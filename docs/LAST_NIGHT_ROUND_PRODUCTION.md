# 마지막 야간 순회 — 제작·검증 계획

2026-10-17 · 기획 완료 / 단계 1 개발 블록아웃 구현

기준: [전체 기획](LAST_NIGHT_ROUND_DESIGN.md), [대본](LAST_NIGHT_ROUND_SCRIPT.md). 기존 Windows ZIP은 이 기획을 구현한 빌드가 아니다.

현재 구현 범위와 남은 제작 항목은 [개발 블록아웃](LAST_NIGHT_ROUND_BLOCKOUT.md)을 참조한다. 아래 단계별 완료 기준 전체를 충족했다는 의미는 아니다.

## 제작 순서와 완료 기준

| 단계 | 산출물 | 통과 조건 |
|---|---|---|
| 0. 이야기·게임 규칙 | 현재 3개 문서 | 인과·필수 단서·결말·퍼즐 해답·실패 복구가 연결됨 |
| 1. 전체 블록아웃 | 입원실→간호사실→처치/설비→폐쇄 병동→출구 | 임시 도형만으로 처음부터 두 결말까지 도달 가능. 공중 발판/무작위 미로에 의존하지 않음 |
| 2. 첫 두 구역 완성(목표 14~18분) | 튜토리얼·서연 합류·이송 기록·첫 추격 | 처음 보는 사람이 조작/목표/도망갈 곳을 설명 없이 이해함 |
| 3. 전체 진행 구현 | 배전 퍼즐·고백·목소리 구별·마지막 선택 | 역순 조작, 재방문, 실패 후 재시작에도 진행 불가 상태가 없음 |
| 4. 아트·연출 | 실제 맵, 상태별 소품, NPC/적 애니메이션, 조명 | 그림과 충돌/상호작용 위치 일치. 문/계단/출구 식별 가능 |
| 5. 통합 검증·출시 | 검증 기록, Windows 빌드, 릴리스 | 두 결말 직접 플레이, 무음 검증, 필수 검사·빌드 통과 |

단계 1~3에서 전체 흐름을 먼저 검증한다. 화면이 완성돼 보인다는 이유로 플레이 검증이 안 된 상태에서 출시하지 않는다. 이전 턴의 부분 테스트나 기존 엔딩 플레이를 새 기획의 완주 증거로 재사용하지 않는다.

## 상태 설계

진행의 원본은 한 곳에서 관리한다. 문·HUD·기록·NPC가 각각 ‘몇 번째 기록인가’를 계산하지 않는다. 아래는 구현 계약이며 클래스가 이미 존재한다는 뜻이 아니다.

```text
WakeInWard
  -> MetSeoyeon                 [손전등 확보 + 병실 외부 해제 완료]
  -> TransferMismatchFound      [팔찌와 이송 기록 대조]
  -> EscapedFirstPursuit        [안전실 진입 + 추격 종료]
  -> PowerRestored              [퓨즈 설치 + 연결문 회로 공급]
  -> EscapedSecondPursuit       [유지 보수 통로 도착]
  -> LockTruthFound             [잠금 이력 확인 + 고백 완료]
  -> ReunitedAtExit             [실제 서연 확인 + 최종 제어반 도달]
  -> FinalPowerSelected         [연결문 유지 또는 주 출구 우선]
  -> EscapedTogether / EscapedAlone
```

독립 상태: 회로 3개의 공급 여부, 퓨즈 장착, 각 문 개폐, 순회자 상태, 서연 구역/행동, 핵심 증거 집합, 선택 기록 집합, 현재 체크포인트. 추격 1/2/3마다 `notStarted / active / resolved`를 따로 저장한다. 같은 스위치를 여러 번 눌러도 NPC나 추격이 복제되지 않는다.

결말은 마지막 대사 선택 문자열로 결정하지 않는다. 전력 경로와 실제 통과 이벤트로 확정한다. 잘못된 순서의 이벤트는 진행을 건너뛰지 않고 무시/안내한다. 반복 읽기와 반복 대화는 보상을 복제하지 않는다.

## 체크포인트 계약

저장 지점: 첫 병실에서 조작 학습 후, 추격 1 전의 안전한 간호사실, 추격 1 종료, 배전 퍼즐 시작, 추격 2 종료, 고백 완료, 최종 선택 직전. 추격 도중 자동 저장하지 않는다.

저장 항목: 진행 단계, 필수 아이템, 회로/퓨즈/문 상태, 증거, NPC의 논리적 위치, 추격 완료 여부. 실패 시 같은 스냅샷으로 복원한다. 적이 플레이어 위에 남거나 진행은 되돌아갔는데 문만 열린 상태가 생기지 않아야 한다.

최종 선택 직전 체크포인트를 남겨 사망 후 두 경로를 다시 선택할 수 있다. 새 게임은 전체 초기화한다. v1은 종료 후 이어하기를 지원하도록 저장 형식/버전을 명시하고, 기존 메모리 체크포인트만으로 ‘저장 완료’ 표시를 하지 않는다. 이전 버전 저장과 호환되지 않으면 시작 전 명확히 안내한다.

## 맵 연결과 서연의 이동

```text
입원실 ─ 복도 ─ 간호사실 ─ 처치/설비 구역 ─ 폐쇄 병동 ─ 최종 출구
                  │                              │         │
                  └── 서연의 유지 보수 우회 통로 ─┴─ 관찰창 ─ 연결문
```

첫 합류 때는 같은 복도에서 동행한다. 간호사실에서 서연이 우회 통로로 들어가는 장면을 보여 준다. 그 뒤 무전과 관찰창의 서연은 같은 통로 안에 있다. 마지막 연결문에서 실제로 합류한다. 동선이 다르다는 이유로 NPC를 임의의 층에 순간 이동시키지 않는다.

## 화면·입력 계약

- 상호작용 후보는 한 번에 하나. 키 안내는 HUD의 한 위치에 표시하고 표지/대사와 겹치지 않는다.
- 문 방향과 벽 방향 일치. 열린 문은 벽/통로에 맞는 자세로 남고 갑자기 삭제되지 않는다.
- 조사 화면과 인벤토리에서 이동·추격·배터리 소모 중지. 닫으면 이전 상태 복원.
- 대화 중 입력 잠금은 한 소유자가 관리하고 씬 전환·중단·실패에서도 해제된다.
- 무전/방송/가까운 대화를 자막에서 구별. 소리 없이도 퍼즐 정보와 위협 경고를 읽을 수 있다.
- 화면 흔들림/섬광 감소, 길게 누르기 대체 입력 제공. 적 접근 자체를 무조건 큰 섬광으로 표현하지 않는다.
- 보급·긴장 수치의 튜닝은 분량 확인 뒤 진행. 무한 소모 타이머로 읽기 시간을 재촉하지 않는다.

## 아트 제작 목록

필수: 입원실 침상/개폐 서랍/관찰창, 간호사실 이송함/호출판/카운터, 처치실 배전반/퓨즈함/방화문, 폐쇄 병동 제어반/관찰 유리, 마지막 연결문/수동 손잡이/새벽 외부.

인물: 루시 이동·조사·손잡이·포획, 서연 대기·동행·달리기·문 조작·문 버티기, 순회자 순찰·탐색·발견·추격·문 압박·포획. 측면과 뒷모습을 별도 준비하고 초상화 그림을 월드 캐릭터로 쓰지 않는다.

각 상태별 sprite의 발 기준점, PPU, 최대 크기, 투명 여백을 통일한다. 개폐 물체는 그림만 바꾸지 않고 애니메이션 중 충돌 갱신 시점을 정한다. 상태가 바뀌는데 항상 닫힌 그림을 보여 주는 현재 일부 가구 표현은 새 제작 완료 기준을 충족하지 못한다.

## 검증표

| 검사 | 통과 조건 |
|---|---|
| 첫 플레이 튜토리얼 | 안내 없이 시작한 사람이 손전등과 문을 찾고 첫 목적지를 이해 |
| 필수 단서 | 선택 기록을 전부 건너뛰어도 진실과 두 결말에 접근 가능 |
| 전력 퍼즐 | 가능한 회로 조합마다 되돌아갈 길 존재, 필수 퓨즈 분실 없음 |
| NPC 연속성 | 서연의 모든 등장/퇴장을 이동 경로로 설명 가능 |
| 추격 | 경고→발견→추격→해제 순서, 벽/닫힌 문 통과 없음, 같은 이벤트 중복 없음 |
| 무음 플레이 | 방송 구별·위협 경고·퍼즐 완료를 자막/시각으로 이해 |
| 포획·재시도 | 입력/시간/카메라/음량/문/NPC/적 상태가 정확히 복원 |
| 낮은 자원 | 배터리 0·긴장 최대에서도 필수 진행이 막히지 않음 |
| 결말 A | 연결문 유지, 수동 해제, 두 인물 실제 통과 확인 |
| 결말 B | 주 출구 우선, 결과 설명, 루시 실제 통과 확인 |
| 저장 | 종료 후 이어하기, 새 게임 초기화, 버전 불일치 처리 |
| 맵 시각 | 문·계단·가구 그림과 이동/상호작용 판정 일치, 과도한 어둠/표시 겹침 없음 |
| 빌드 | 필수 검사와 Windows 빌드 통과, 배포 ZIP이 검증한 소스와 동일 |

직접 플레이 기록에는 빌드 식별자, 선택 경로, 소요 시간, 실패/재시작, 확인한 장면을 남긴다. 상태 주입·포털 직접 호출·자동 시뮬레이션은 별도로 표시한다. 무음 테스트에서는 음성·효과음을 ‘들어서 확인했다’고 기록하지 않는다.
